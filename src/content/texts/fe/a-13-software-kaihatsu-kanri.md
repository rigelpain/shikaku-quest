## この分野の位置づけ
開発プロセスのモデル（ウォーターフォール、アジャイルなど）と、構成管理や知的財産の扱いを含む開発管理の考え方を扱います。出題は2問前後ですが、システム開発技術とプロジェクトマネジメントの橋渡しとなる知識です。

## 要点
- ウォーターフォールは工程を順に進め後戻りしない前提のモデルで、大規模で要件が固まった開発に向きます。
- プロトタイピングは試作品で利用者の要求を早期に確認し、スパイラルは分析・設計・実装・評価を繰り返して段階的に拡張します。
- アジャイル開発は短い反復で動くソフトを届け、変化に対応します。アジャイルソフトウェア開発宣言の4つの価値を押さえます。
- スクラムではプロダクトオーナー、スクラムマスター、開発者の3つの役割と、スプリント・デイリースクラム・レトロスペクティブなどのイベントがあります。
- XP の実践：テスト駆動開発、ペアプログラミング、リファクタリング、継続的インテグレーション。
- DevOps は開発と運用が協力し、CI/CD で自動的にビルド・テスト・デプロイする文化と仕組みです。
- 構成管理はソースやドキュメントのバージョンを管理し、変更の履歴と影響を追跡します。
- 共通フレーム（SLCP）は発注者と受注者が同じ言葉で工程を話すための枠組みです。

## 頻出用語
- **ウォーターフォールモデル** — 工程を上流から下流へ順に進める開発モデル。
- **スパイラルモデル** — リスク分析を含む反復で段階的に完成させるモデル。
- **プロトタイピング** — 試作を作って要求を確認する手法。
- **アジャイル** — 短い反復と顧客との協調を重視する開発の考え方の総称。
- **スクラム** — 役割・イベント・成果物を定めたアジャイルの枠組み。
- **スプリント** — スクラムの固定長の反復期間。通常1〜4週間。
- **プロダクトバックログ** — 実現したい機能を優先順に並べた一覧。
- **テスト駆動開発（TDD）** — 先にテストを書き、それを通すコードを書く手法。
- **ペアプログラミング** — 2人で1台の画面を使い対話しながら開発する手法。
- **継続的インテグレーション（CI）** — コードを頻繁に統合し自動テストする仕組み。
- **DevOps** — 開発と運用が連携して素早く安定的に価値を届ける取組み。
- **リバースエンジニアリング** — 既存のプログラムから設計情報を取り出すこと。
- **構成管理** — 成果物のバージョンや変更履歴を管理する活動。
- **マッシュアップ** — 複数の Web サービスを組み合わせて新しいサービスを作ること。

## よくある引っかけ
- アジャイルは「計画しない」「ドキュメントを書かない」ではありません。宣言は「左記も価値があるが右記をより重視する」という表現です。
- スクラムマスターは管理者ではなく、チームがスクラムを実践できるよう支援する役割です。優先順位を決めるのはプロダクトオーナーです。
- スパイラルとプロトタイピングは似ていますが、スパイラルは毎回リスク評価を行い本番品質のものを積み上げます。
- CI と CD は別の概念です。CI は統合とテスト、CD はリリース可能な状態の維持や配備まで含みます。
- ウォーターフォールの弱点は「後工程で要件の誤りが見つかると手戻りが大きい」ことです。

## 確認クイズ
Q1. スクラムでプロダクトバックログの優先順位に責任を持つ役割は何ですか。
→ 答え：プロダクトオーナー（プロダクトの価値を最大化する責任を負う役割のため）。

Q2. コードを書く前にそのコードが満たすべきテストを先に書く開発手法は何ですか。
→ 答え：テスト駆動開発（失敗するテストを書いてから通すコードを書く手法のため）。

Q3. 要件があいまいで利用者の確認を早く取りたいとき、適した開発手法は何ですか。
→ 答え：プロトタイピング（試作品を見せて要求を具体化できるため）。
