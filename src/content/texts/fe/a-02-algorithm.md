## この分野の位置づけ
科目Aでは数問ですが、科目Bの20問中16問がこの分野の擬似言語問題なので、FE全体で最も配点の重い領域です。科目Aでは「どのデータ構造・アルゴリズムが何に向くか」「計算量はどのオーダーか」という知識問題が中心です。

## 要点
- 配列は添字で直接アクセスでき O(1)、連結リストは挿入・削除が得意ですがたどるのに O(n) かかります。
- スタックは LIFO（後入れ先出し）、キューは FIFO（先入れ先出し）です。関数呼出しや逆ポーランド記法の評価はスタック、待ち行列はキューです。
- 2分探索木は「左 < 親 < 右」を保つ木で、バランスが取れていれば探索は O(log n) です。
- ヒープは親が子より常に大きい（または小さい）完全2分木で、優先度付きキューの実装に使います。
- 線形探索は O(n)、2分探索は整列済み配列に対して O(log n) です。
- 整列はバブル・選択・挿入が O(n^2)、クイック・マージ・ヒープが平均 O(n log n) です。
- ハッシュ表は平均 O(1) で探索できますが、衝突（シノニム）の処理が必要です。
- 再帰は「終了条件」と「自分より小さい問題への呼出し」の2点で読みます。
- 言語の分類（手続き型、オブジェクト指向、関数型、スクリプト言語）とコンパイラ・インタプリタの違いも問われます。

## 頻出用語
- **計算量（オーダー）** — 入力サイズ n に対する処理時間の増え方。O(1) < O(log n) < O(n) < O(n log n) < O(n^2)。
- **スタック** — push/pop で末尾を操作する LIFO 構造。
- **キュー** — enqueue/dequeue で先頭から取り出す FIFO 構造。
- **連結リスト** — 要素がポインタで次の要素を指す構造。
- **2分探索木** — 左部分木 < 節 < 右部分木 を満たす木。
- **ヒープ** — 親子関係に大小の制約がある完全2分木。
- **ハッシュ法** — キーから関数で格納位置を求める方法。
- **シノニム** — ハッシュ値が同じになる別キーの衝突。
- **安定な整列** — 同じキーの要素の順序を保つ整列。マージ整列は安定、クイック整列は不安定。
- **再帰** — 関数が自分自身を呼び出すこと。階乗やハノイの塔が典型。
- **コンパイラ** — ソース全体を機械語に翻訳してから実行する方式。
- **インタプリタ** — 1文ずつ解釈しながら実行する方式。
- **ガーベジコレクション** — 使われなくなったメモリを自動回収する仕組み。

## よくある引っかけ
- 2分探索は「整列済み」が前提です。未整列の配列には使えません。
- クイック整列は平均 O(n log n) ですが最悪 O(n^2) になります。「常に高速」ではありません。
- スタックに A, B, C の順で push して pop すると C, B, A の順に出ます。順番の反転を見落とさないようにします。
- 木の「深さ」と「高さ」、「節」と「葉」など用語の指す範囲を確認しましょう。葉は子を持たない節です。
- O(n log n) の log の底は問いません。定数倍はオーダーでは無視します。

数値例：n = 1,000 の整列済み配列を2分探索すると、比較回数は最大で約 log2 1000 ≒ 10 回です。線形探索なら最大 1,000 回です。

## 確認クイズ
Q1. 関数呼出しの戻り先を管理するのに向くデータ構造はどれですか。
→ 答え：スタック（最後に呼ばれた関数から先に戻るので LIFO が合うため）。

Q2. 要素数が4倍になったとき、O(n^2) のアルゴリズムの処理時間はおよそ何倍になりますか。
→ 答え：16倍（4 の2乗になるため）。

Q3. 連結リストが配列より有利な操作は何ですか。
→ 答え：途中への挿入と削除（ポインタの付け替えだけで済み、要素の移動が不要なため）。
