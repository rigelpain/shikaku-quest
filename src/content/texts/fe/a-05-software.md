## この分野の位置づけ
OS の役割（タスク管理、記憶管理、ファイル管理）と、ミドルウェア、OSS を扱います。コンピュータ構成要素と密接に関係し、特に仮想記憶のページ置換えやタスクの状態遷移は手を動かす問題として出ます。

## 要点
- OS はハードウェアを抽象化し、タスク管理・記憶管理・ファイル管理・入出力管理・ユーザー管理を担います。
- タスク（プロセス）は実行可能・実行・待ちの3状態を遷移します。入出力要求で「待ち」に入り、完了で「実行可能」に戻ります。
- スケジューリングにはラウンドロビン、優先度順、到着順などがあり、プリエンプティブ方式では OS が強制的に CPU を奪います。
- 仮想記憶はページング方式で主記憶より大きな空間を扱い、ページ置換えには FIFO や LRU を使います。
- ページフォールトが多発して処理が進まない状態をスラッシングと呼びます。
- 多重プログラミングは入出力待ちの時間に別タスクを実行して CPU 利用率を上げます。
- ファイルシステムでは絶対パスと相対パス、ディレクトリ構造、アクセス権の読み方を押さえます。
- OSS はソースが公開され、ライセンス（GPL、BSD、MIT、Apache）によって改変版の公開義務が異なります。
- ミドルウェアは OS とアプリの間に位置し、DBMS や Web サーバが代表例です。

## 頻出用語
- **カーネル** — OS の中核で、資源管理を行う部分。
- **プロセス／スレッド** — 実行中のプログラム単位／プロセス内の軽量な実行単位。
- **ディスパッチャ** — 実行可能状態のタスクに CPU を割り当てる機能。
- **ラウンドロビン** — 一定時間ずつ順番に CPU を割り当てる方式。
- **プリエンプション** — 実行中のタスクから OS が CPU を取り上げること。
- **ページング** — 主記憶とプログラムを固定長のページで管理する方式。
- **LRU** — 最も長く使われていないページを追い出す置換えアルゴリズム。
- **スラッシング** — ページ置換えが頻発して実処理が進まない状態。
- **デッドロック** — 複数タスクが互いの資源解放を待って止まる状態。
- **セマフォ** — 排他制御のための同期機構。
- **API** — プログラムから OS や他ソフトの機能を呼び出す窓口。
- **GPL** — 改変して配布する場合にソースの公開を義務づける OSS ライセンス。
- **ファームウェア** — ハードウェアに組み込まれた制御用ソフト。

## よくある引っかけ
- 「実行」から「待ち」へは入出力要求で遷移し、「待ち」から直接「実行」には戻れません。必ず「実行可能」を経由します。
- LRU は「最も長く使われていない」、FIFO は「最も古く読み込んだ」ページを追い出します。参照順の表を書いて比べましょう。
- 主記憶を増やしても CPU 利用率が上がらないのは CPU がボトルネックのときです。スラッシングなら主記憶の増設で改善します。
- OSS は「無料」ではなく「ソースが公開されていて自由に使える」が定義です。商用利用も可能です。
- 相対パスの「..」は1つ上のディレクトリ、「.」は現在のディレクトリです。

数値例：ページ枠が3つで参照順が 1, 2, 3, 1, 4 のとき、LRU では 4 を読む時点で最も長く使われていない 2 が追い出されます。FIFO なら最初に入った 1 が追い出されます。

## 確認クイズ
Q1. 入出力完了の割込みを受けたタスクは、どの状態に遷移しますか。
→ 答え：実行可能状態（CPU の割当てを待つ状態に戻るため）。

Q2. ページフォールトが頻発し、ページの入替えばかりで処理が進まない現象を何といいますか。
→ 答え：スラッシング（主記憶不足で置換えが連続するため）。

Q3. GPL と BSD ライセンスの主な違いは何ですか。
→ 答え：改変版の配布時にソース公開を義務づけるのが GPL で、BSD にはその義務がないこと。
