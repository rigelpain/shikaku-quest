## この分野の位置づけ
科目Aで最も出題数が多い分野で、毎回10問前後出ます。科目Bでも4問が情報セキュリティです。暗号、認証、攻撃手法と対策、マネジメント（ISMS）と法制度までを横断的に問われます。

## 要点
- 情報セキュリティの3要素は機密性・完全性・可用性です。追加で真正性・責任追跡性・否認防止・信頼性も挙げられます。
- 共通鍵暗号（AES）は鍵の共有が課題、公開鍵暗号（RSA、楕円曲線）は公開鍵で暗号化し秘密鍵で復号します。
- デジタル署名は送信者の秘密鍵で署名し、受信者が送信者の公開鍵で検証します。改ざん検知と否認防止に使います。
- PKI では認証局（CA）が公開鍵の正当性を証明書で保証します。
- ハッシュ関数（SHA-256）は一方向で固定長、わずかな入力差で全く異なる値になります。パスワードはソルト付きハッシュで保存します。
- 認証の3要素は知識（パスワード）・所持（IC カード）・生体（指紋）で、2つ以上を組み合わせるのが多要素認証です。
- 代表的な攻撃：SQL インジェクション、XSS、CSRF、フィッシング、DoS/DDoS、ランサムウェア、標的型攻撃、パスワードリスト攻撃。
- 対策技術：ファイアウォール、IDS/IPS、WAF、DMZ、VPN、TLS、多要素認証、入力値の検証。
- ISMS は PDCA でリスクを管理し、リスク対応は回避・低減・移転・受容の4種類です。

## 頻出用語
- **機密性／完全性／可用性** — 許可された者だけが見られる／改ざんされない／必要なときに使える。
- **共通鍵暗号** — 暗号化と復号に同じ鍵を使う方式。高速だが鍵配送が課題。
- **公開鍵暗号** — 公開鍵と秘密鍵のペアを使う方式。鍵配送問題を解決する。
- **ハイブリッド暗号** — データは共通鍵で、共通鍵の受渡しは公開鍵で行う方式。TLS で使う。
- **デジタル署名** — 送信者の秘密鍵で作る改ざん検知と本人証明の仕組み。
- **認証局（CA）** — 公開鍵証明書を発行し、公開鍵の持ち主を保証する機関。
- **SQL インジェクション** — 入力欄に SQL を混入させて DB を不正操作する攻撃。
- **XSS** — Web ページに悪意あるスクリプトを埋め込み閲覧者の環境で実行させる攻撃。
- **CSRF** — ログイン済み利用者に意図しないリクエストを送らせる攻撃。
- **DMZ** — 外部公開サーバを置くため内部ネットワークと分離した領域。
- **WAF** — Web アプリケーションへの攻撃を検知・遮断するファイアウォール。
- **IDS／IPS** — 不正侵入を検知する／検知して遮断する装置。
- **リスクアセスメント** — リスクの特定・分析・評価の一連の作業。
- **ゼロデイ攻撃** — 修正プログラムが公開される前の脆弱性を突く攻撃。
- **ソーシャルエンジニアリング** — 人間の心理や行動の隙を突いて情報を得る手口。

## よくある引っかけ
- 暗号化は「受信者の公開鍵」、署名は「送信者の秘密鍵」で行います。どちらの鍵で何をするかを毎回確認しましょう。
- SQL インジェクション対策はプレースホルダ（バインド機構）、XSS 対策は出力時のエスケープです。対策を入れ替えると誤答です。
- IDS は検知のみ、IPS は遮断まで行います。
- リスク移転は保険加入や外部委託、リスク回避は業務そのものをやめることです。「低減」と混同しないようにします。
- ハッシュは「復号できない」のが特徴です。暗号化と違い、元に戻す鍵はありません。

## 確認クイズ
Q1. 送信者が本人であることと内容が改ざんされていないことを同時に保証する技術は何ですか。
→ 答え：デジタル署名（送信者の秘密鍵で署名し公開鍵で検証するため）。

Q2. 入力値を SQL 文に直接連結しないことで防げる攻撃は何ですか。
→ 答え：SQL インジェクション（プレースホルダで入力をデータとして扱うため）。

Q3. リスクに備えてサイバー保険に加入することは、リスク対応のどれに当たりますか。
→ 答え：リスク移転（損失の負担を第三者に移すため）。
