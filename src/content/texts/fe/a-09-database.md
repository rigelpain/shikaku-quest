## この分野の位置づけ
科目Aで毎回3〜4問出る主要分野です。関係モデル、正規化、SQL、トランザクション管理が中心で、応用情報の科目Bや実務のデータ設計にも直結します。

## 要点
- 関係データベースは表の集まりで、行がレコード、列が属性です。主キーは行を一意に識別し、外部キーは他の表の主キーを参照します。
- 第1正規形は繰返し項目の排除、第2正規形は部分関数従属の排除、第3正規形は推移的関数従属の排除です。
- 関係演算は選択（行の抽出）、射影（列の抽出）、結合（表の連結）の3つを区別します。
- SQL の SELECT は WHERE で絞り込み、GROUP BY で集計、HAVING で集計後の条件、ORDER BY で並べ替えをします。
- トランザクションの ACID 特性（原子性・一貫性・独立性・耐久性）を押さえます。
- 排他制御では共有ロック（読取り）と専有ロック（更新）があり、互いの解放を待ち合う状態がデッドロックです。
- 障害回復ではロールバック（更新前ログで取消し）とロールフォワード（更新後ログで再現）を使い分けます。
- インデックスは検索を速めますが更新時のコストが増えます。
- データウェアハウス、データマイニング、NoSQL（KVS、ドキュメント型）など分析系の用語も出ます。

## 頻出用語
- **主キー** — 行を一意に識別する属性。NULL は許されない。
- **外部キー** — 他の表の主キーを参照する属性。参照整合性を保つ。
- **関数従属** — A の値が決まれば B の値が決まる関係。
- **正規化** — 冗長性と更新時の矛盾をなくすよう表を分割すること。
- **E-R 図** — 実体と関連で業務のデータ構造を表す図。
- **選択／射影／結合** — 行の抽出／列の抽出／複数表の連結。
- **ビュー** — SELECT 文で定義される仮想的な表。
- **GROUP BY** — 指定列の値ごとに行をまとめて集計する句。
- **HAVING** — 集計結果に対して条件を付ける句。
- **ACID** — トランザクションが満たすべき4つの性質。
- **コミット／ロールバック** — 更新の確定／取消し。
- **2相コミット** — 分散データベースで全サイトの合意を取ってから確定する方式。
- **ロールフォワード** — バックアップ以降の更新後ログで障害直前の状態に戻す回復。
- **インデックス** — 検索を高速化する索引。B木構造が一般的。

## よくある引っかけ
- WHERE は「集計前」の行に対する条件、HAVING は「集計後」のグループに対する条件です。集計関数を WHERE に書くと誤りです。
- 選択は「行」、射影は「列」です。漢字のイメージと逆に感じる人が多いので声に出して覚えましょう。
- 主キーは NULL 不可ですが、外部キーは NULL を許す場合があります。
- ロールバックは「進行中の取引を取り消す」、ロールフォワードは「ディスク障害後にバックアップから再現する」場面で使います。
- 正規化を進めるほど結合が増えて検索性能は落ちることがあります。あえて非正規化する判断もあります。

```text
SELECT 部署, COUNT(*) FROM 社員
  WHERE 入社年 >= 2020
  GROUP BY 部署
  HAVING COUNT(*) >= 3
```
この文は 2020年以降入社の社員を部署ごとに数え、3人以上の部署だけ返します。

## 確認クイズ
Q1. 「社員番号 → 氏名」のように、ある属性の値が決まると別の属性の値が決まる関係を何といいますか。
→ 答え：関数従属（正規化の判断基準になる関係のため）。

Q2. ディスク障害でデータベースが壊れたとき、バックアップと更新後ログを使って復旧する方法は何ですか。
→ 答え：ロールフォワード（バックアップ時点以降の更新を再適用して障害直前に戻すため）。

Q3. 表から特定の列だけを取り出す関係演算は何ですか。
→ 答え：射影（列を取り出す演算で、行を取り出す選択と区別するため）。
